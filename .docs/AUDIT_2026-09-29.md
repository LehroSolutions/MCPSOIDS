# Security and quality audit — 2026-09-29

Scope: `mcp_server_ref/` (the MCP server: transport, security manager, governance,
tools) plus repo integrity, CI, and the container build.

Baseline before: `bun run verify` green — lint 0 errors / 28 warnings, prettier clean,
`tsc` OK, **no test suite existed**.
Baseline after: `bun run verify` green — lint 0 errors / 27 warnings, prettier clean,
`tsc` OK, **22 tests passing across 3 files**.

## Fixed in this pass

### 1. Symlink escape from the filesystem sandbox — High

`src/features/security.ts` canonicalized paths with `path.resolve` only, so a symlink or
Windows junction *inside* an allowed root escaped the sandbox. `../` traversal was already
blocked, but `root/link -> C:\Users\<u>\.ssh` made `link/id_rsa` "allowed".

`validatePath` now canonicalizes with `fs.realpathSync.native` before the containment
check, and allowed roots are canonicalized in the constructor. Because a write target may
not exist yet, resolution walks up to the nearest existing ancestor and re-appends the
missing segments, so a not-yet-created leaf cannot smuggle a symlinked parent.

Regression test: `test/security.test.ts` > "blocks a symlink that escapes an allowed root".

### 2. Absolute path disclosure to unauthenticated clients — Medium

The rejection message embedded `this.allowedRoots.join(', ')` and was returned verbatim to
the caller, publishing the server's root paths. The message now names only the denied
path. Regression test asserts the roots no longer appear in the message.

### 3. Quadratic audit log appends — High

Every `append` called `getLastEntryHash()`, which read and `JSON.parse`d the entire JSONL
file, making appends O(n) and the log O(n²) overall. The last hash is now cached in memory
and initialized once via a bounded 64 KiB tail read, with a full-read fallback so an
oversized final line cannot silently break the chain. Regression test: "a fresh instance
continues the chain of an existing log".

### 4. Unauthenticated, unthrottled full-log reads — High

The rate limiter was mounted only on `/mcp`. `/audit/entries` and `/audit/integrity` read
the whole log per request and had no limit. They now share a tighter limiter (120 per
15 min), along with `/metrics` and `/.well-known`.

### 5. Stack traces returned to clients — Medium

There was no terminating error handler, so `next(err)` reached Express's `finalhandler`,
which serialises the full stack trace and absolute paths whenever `NODE_ENV` is not
`production` — and `NODE_ENV` **defaults to `development`**. A terminal handler now logs
server-side and returns a generic 500.

### 6. Hardcoded admin credentials in source — Medium

`src/tools/businsistoid.ts` committed `admin@example.com` / `password123`, auto-used to
fetch an admin JWT, and fell back to an empty token on failure (sending
`Authorization: Bearer ` with no credential). Credentials now come from
`BUSINSISTOID_ADMIN_EMAIL` / `BUSINSISTOID_ADMIN_PASSWORD`, fail loudly when absent, and
the empty-token fallback is gone. The tool remains unreachable over HTTP.

### 7. Prototype pollution via `__proto__` — Low

`stripUndefined` in `auditLog.ts` assigned JSON-derived own keys onto a plain object,
invoking the `__proto__` setter. It now builds with `Object.create(null)`.

### 8. Container image could not build — Low

`mcp_server_ref/Dockerfile` used `node:20-alpine` against `engines.node >= 24`, and ran
`npm ci` when no `package-lock.json` exists. It now uses `node:24-alpine`, bootstraps the
pinned Bun, and installs with Bun. It also gained a fail-fast `ENTRYPOINT` guard that
refuses to start without `MCP_AUTH_TOKEN`, rather than defaulting to no auth.

### 9. Dependency CVE auditing disabled — Low

`.npmrc` set `audit=false`, so CVEs never surfaced on install. Now `audit=true`.

### 10. Unbounded `delay_ms` — Low

`src/tools/echo.ts` had no upper bound on `delay_ms`; now capped at 60000.

### 11. No test suite and no CI test gate — High

The repo had no `test` script at all and CI never ran tests, so the manual checks in
`scripts/inspector.ts` were the only verification and nothing ran automatically. Added
`test/security.test.ts`, `test/audit-log.test.ts`, and `test/debug-tools.test.ts` (22 tests
total) covering sandbox containment, symlink escape, path disclosure, hash-chain integrity,
tamper detection, cold-start chain continuation, the debug-tool opt-in gate, and event-loop
yielding. `test` was added to `mcp_server_ref/package.json`, to root `verify`, and to
`.github/workflows/ci.yml`.

### 12. `__debug_stress` was exposed by default with no auth — Critical (approved fix)

`src/index.ts` enabled debug tools whenever `NODE_ENV === 'development'`, and
`src/config.ts` defaults `NODE_ENV` to `'development'`, so the shipped `start` script — which
sets no `NODE_ENV`, and no `MCP_AUTH_TOKEN` — exposed a denial-of-service tool to anyone who
could reach the port.

- Debug tools now require an explicit `MCP_ENABLE_DEBUG_TOOLS=true`. The derivation moved
  into a pure `resolveDebugToolsEnabled(config)` in `src/config.ts` so it is testable
  without reloading modules; `NODE_ENV` deliberately no longer enables it. The tool's public
  shape is unchanged.
- `mode: 'memory'` ceiling reduced from 1000 MB (1 GB per call) to **256 MB**, with the
  published JSON Schema bound kept in agreement with the zod schema.
- `mode: 'cpu'` no longer busy-loops synchronously. It burns in 8 ms slices and yields via
  `setImmediate`, so timers, transport requests, and `/metrics` stay serviced and the
  request timeout is no longer defeated. Total duration semantics are unchanged.

9 tests added in `test/debug-tools.test.ts`, including one that asserts a zero-delay timer
still fires during a burn (the event loop is demonstrably not starved).

### 13. `mcp-control-center` was an unregistered submodule — High (approved fix)

It was a gitlink (mode `160000`) in `HEAD` pointing at `9352d1a` with no `.gitmodules`, so
the whole Next.js control center was untracked and a fresh clone did not obtain it.

The pre-vendoring history was confirmed recoverable before anything was removed:
`../.archive/mcp-control-center-history.bundle` contains exactly `9352d1a` on
`refs/heads/master` and `HEAD`, and `git bundle verify` reports a complete history. The
nested `.git` was then removed and the 39 source files (220 KB) staged as regular blobs.
Verified afterwards: no `160000` entry remains anywhere in the repo, all 39 entries are mode
`100644`, and no `node_modules`, `.next`, `test-results`, or `playwright-report` path is
tracked. `AGENTS.md` was corrected, because it still described the directory as a submodule
and told agents to keep changes out of the parent repo — guidance that was actively wrong
and would have misled every future agent.

Recovery remains possible at any time:
`git clone ../.archive/mcp-control-center-history.bundle mcp-control-center`.

## Documented, not changed — needs sign-off

`AGENTS.md` requires human approval before changing the MCP tool surface or the `start`
flags, and before touching the submodule pointer:

- **No authentication unless `MCP_AUTH_TOKEN` is set.**
- **`--cors-origin` is unvalidated** and `--cors-allow-all` is blocked only when
  `NODE_ENV === 'production'`, which `start` never sets.
- **`docker-compose.yml:14,30` default `MCP_AUTH_TOKEN` to `change-me-mcp-token`**, which
  satisfies the new container guard with a publicly known value.
- **`mcp_server_ref/.tool-versions` says `bun 1.2.19`** while the root says `bun 1.3.14`,
  matching `packageManager` and CI.
- **Stale toolchain.** `eslint` 8.57.1 (EOL) and `@typescript-eslint` 6.21.0 are two majors
  behind; `@types/node` is 20.19.43 against `engines.node >= 24`, so Node 24 APIs are
  untyped.
- **Root files are never format-checked.** Root `format:check` delegates entirely into
  `mcp_server_ref`, so root markdown, JSON, and the CI workflow are unformatted by any gate.
- **DNS-rebinding analogue.** The in-memory `lastEntryHash` cache assumes a single writer;
  multiple processes appending to one log would diverge.
